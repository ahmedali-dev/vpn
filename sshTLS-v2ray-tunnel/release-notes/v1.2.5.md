TunnelNest 1.2.5 fixes control sessions and improves connection startup diagnostics.

- Keep the private session token in the control URL fragment so refresh works even when embedded browsers discard session storage.
- Return JSON authentication errors and explain missing or expired sessions instead of displaying unexpected-token errors.
- Open the browser in the invoking user's graphical session when running `sudo tunnel -ui` on macOS or Linux.
- Verify HTTPS through SOCKS before marking SSH or Xray connections active. Report upstream failures and avoid enabling full-device routes when verification fails.
- Keep proxy-only traffic opt-in per application; configure SOCKS5/PAC or choose full-device TUN to route other apps.

Download the TunnelDesktop archive for your operating system and extract the entire folder before launching. Standalone engines are in TunnelCLI archives. SHA256SUMS.txt covers all downloads. Keep the complete control URL private.

Packages remain unsigned and macOS packages are not notarized. The browser launcher requires a graphical session. Automated tests do not establish live server availability or validate all native desktop and TUN behavior. A failed HTTPS check requires examining the connection log; this update cannot repair expired accounts or an unreachable provider.
